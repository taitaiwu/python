❯ 如果 rioxarray 不加 maskded=True 他的 nodata 值會是多少                       

● 不加 masked=True 時，rioxarray 不會替換任何值。nodata 像素保留檔案原本記錄的 
  nodata 值，所以沒有固定答案，要看你的 GeoTIFF 怎麼存：

  ┌────────────────────┬───────────────────────────┬────────────────────────┐
  │        情況        │     不加 masked=True      │     加 masked=True     │
  ├────────────────────┼───────────────────────────┼────────────────────────┤
  │ 檔案有設定         │                           │ 這些像素變成           │
  │ nodata（例如       │ 陣列裡就是那個數字，da.ri │ NaN，da.rio.nodata     │
  │ -9999、-32768、-3. │ o.nodata 會回傳它         │ 變成 nan，原本的值移到 │
  │ 4e38）             │                           │  da.rio.encoded_nodata │
  ├────────────────────┼───────────────────────────┼────────────────────────┤
  │ 檔案沒有設定       │ 值不變，da.rio.nodata 是  │ 一樣不會遮罩任何像素， │
  │ nodata             │ None                      │ 因為沒有 nodata        │
  │                    │                           │ 可以對應               │
  ├────────────────────┼───────────────────────────┼────────────────────────┤
  │ 資料型別           │ 維持原本的型別（例如      │ 會轉成 float，因為 NaN │
  │                    │ int16）                   │  只能存在浮點數裡      │
  └────────────────────┴───────────────────────────┴────────────────────────┘

  怎麼確認你的檔案

  import rioxarray

  dem = rioxarray.open_rasterio(RAW_DIR / "你的DEM.tif")
  print(dem.rio.nodata)   # 檔案設定的 nodata 值；None 表示沒設定
  print(dem.dtype)        # 原始資料型別

  為什麼要注意

  不加 masked=True 時，nodata 會被當成一般數值參與計算。例如 nodata 是 -9999，算
  平均高程或畫圖時，就會出現極端的負值，色階也會被拉壞。解決方法有兩種：

  - 讀檔時加 masked=True（最簡單）
  - 自己遮罩：dem.where(dem != dem.rio.nodata)

  如果你需要，我可以幫你查 data/raw/ 裡那幾個 DEM 實際設定的 nodata
  值。只會讀取檔案，不會修改。

● 不是 rioxarray 的預設值。rioxarray 本身不會產生 nodata 值。-32767
  是資料提供者寫進 GeoTIFF 的設定，rioxarray 只是照著讀出來。

  -32767 的由來

  DEM 常用 int16 存（範圍 -32768 到
  32767）。製作者會挑一個真實高程不可能出現的數字當
  nodata，通常選在型別的最小值附近：

  - -32768：int16 的最小值，很多 GIS 軟體會用它
  - -32767：最小值加 1，也很常見，例如 NetCDF 對 short 型別的預設填充值就是它

  所以「挑極低值當
  nodata」這個理解是對的。不過「預設」指的是製作者的慣例，不是程式的預設。TGEO
  為什麼選 -32767，data/raw/資料來源說明.md
  沒有寫，我無法確認。我本來想直接讀檔驗證，但本機沒有安裝
  rasterio，所以還沒確認到這個檔案的設定。

  要確認的一件事

  你說「算出來」，如果是用 dem.min() 算出 -32767，那代表 nodata 
  像素被當成高程算進去了（海面、縣市界外的範圍都是這個值）。可以在 Colab

❯ 你可以再解釋一下高程的定義嗎 是指最高點嗎                                     

● 不是最高點。高程是某一個位置的地面，比基準面（大約就是平均海平面）高出多少公尺
  。 每個位置都有自己的高程，不是指一個區裡最高的地方。

  在 DEM 裡

  DEM 把地面切成一格一格。你的資料一格是 20 m × 20
  m，每一格只存一個高程值，代表那一格地面的高度。

      ┌────┬────┬────┐
      │ 12 │ 15 │ 21 │   ← 每格一個數字（公尺）
      ├────┼────┼────┤
      │ 10 │ 13 │ 18 │
      └────┴────┴────┘

  一格裡面就算有小坡、房子或水溝，DEM 也只用一個數字代表它，所以 20 m DEM
  看不到比一格還小的起伏。

  在你的作業裡，各種「高程」分別是什麼

  ┌──────────────┬──────────────────────────────────────────────────────────┐
  │  你算的東西  │                           意思                           │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ 步驟二的     │ 整張 DEM 最低和最高的那一格。只有 max()                  │
  │ dem.min()、d │ 才是「最高點」，例如你對照的塔曼山                       │
  │ em.max()     │                                                          │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ 站點的       │ 用 method="nearest"                                      │
  │ 高程_m       │ 取離站點最近那一格的高程，就是站點所在位置的地面高度     │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ 表格的       │ 把一個區所有站點的高程排序，取中間那個                   │
  │ 高程中位數   │                                                          │
  ├──────────────┼──────────────────────────────────────────────────────────┤

❯ 那這樣和海拔有什麼區別                                                        

● 在你的作業裡，高程和海拔可以當成同一件事，兩者都是「比平均海平面高多少」。差別
  主要在用語的場合：

  ┌─────┬──────────────────┬────────────────────────────────────────────────┐
  │ 用  │     常用場合     │                      意思                      │
  │ 語  │                  │                                                │
  ├─────┼──────────────────┼────────────────────────────────────────────────┤
  │ 海  │ 日常生活、登山、 │ 明確以平均海平面為 0 m                         │
  │ 拔  │ 地理課本         │                                                │
  ├─────┼──────────────────┼────────────────────────────────────────────────┤
  │ 高  │ 測量、GIS、地圖  │ 相對於某個「基準面」的高度。基準面通常是平均海 │
  │ 程  │ 資料             │ 平面，這時就等於海拔                           │
  └─────┴──────────────────┴────────────────────────────────────────────────┘

  所以「塔曼山海拔 2130 公尺」和「DEM 高程 2128.46 公尺」可以直接比較，你第 2
  題的做法沒有問題。

  高程這個詞比較廣，是因為基準面可以換。例如工地常用「相對高程」，以某個自訂的點
  為 0；不過你的 DEM 不是這種情況。

  容易混淆的其他「高」

  1. 高度（height）
  指物體本身從地面算起有多高，例如「台北 101 高 508 公尺」。這和高程不同，101
  所在地面的高程只有幾公尺。

  2. GPS 顯示的高度
  手機 GPS 原始算出的是「橢球高」，基準是數學上的地球橢球面，不是海平面。在臺灣
  ，兩者大約差二十多公尺（這是概略值，各地不同）。大部分手機 app
  會自動換算成海拔，但如果你拿 GPS 數字和 DEM
  對照時差了二十幾公尺，可能就是這個原因。

  3. DEM 和 DSM
  DEM（數值高程模型）通常記錄的是裸露地面的高程，已經去掉建築物和樹木。如果把建
  築物頂端、樹冠都算進去，就叫 DSM（數值地表模型）。所以板橋車站那一格的高程是車
  站底下的地面，不是車站屋頂。你這份 TGEO 的 20 m DEM
  屬於哪一種，我沒有查證，要寫進作業的話建議去資料來源頁面確認。

  真正的原因：行政區歸屬

  這站從名稱、地址到編號，看起來都屬於林口區：

  - 站名是「林口婦幼公園」
  - 文化一路是林口的道路
  - StationUID 的編碼方式：林口的站都是 500216xxx（例如林口老街
    NWT500216011），泰山的站是 500220xxx（例如明志科大 NWT500220012）。這站是
    500216033

  但你用 sjoin(predicate="within") 判斷時，站點的座標落在鄉鎮界圖層的泰山區範圍
  內，所以被歸到泰山區。可能的原因有兩種，我目前無法確定是哪一種：

  1. 站點真的位在泰山區境內。
     林口、泰山的區界不一定沿著道路走。泰山區的北邊有一部分延伸到台地上，站點可
     能剛好在區界的泰山那一側，只是營運單位依生活圈把它歸給林口。
  2. 站點座標或區界圖層有誤差。
     站點離區界很近時，幾公尺的誤差就可能讓它落到另一邊。

  會配對到任何一區，包括外縣市。如果你想讓圖上只出現新北市的區，可以把 sjoin
  的對象改成 city（只有新北市）。不過這樣這一站就會配對不到任何區，變成
  NaN。要怎麼處理由你決定。
