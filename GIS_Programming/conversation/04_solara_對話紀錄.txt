❯ 為什麼要用 solara.reactive ，用一般的不行嗎                                   

● 不行，用一般變數會出現「拉了滑桿，畫面卻不會變」的情況。關鍵在 Solara
  怎麼更新畫面。

  Solara 的運作方式

  Page() 是一個函式。Solara 會執行它一次，把結果畫成網頁。之後只有在 Solara 
  知道「有資料變了」的時候，才會再執行一次 Page()，用新的值重新畫面。

  solara.reactive 就是讓 Solara 知道資料變了的機制：

  門檻 = solara.reactive(0)

  1. 使用者拉滑桿，Solara 把新的值存進 門檻。
  2. 門檻 發現自己的值變了，通知所有讀過 門檻.value 的元件。
  3. Page() 重新執行，算出新的表格和圖。

  如果改用一般變數

  門檻 = 0

  @solara.component
  def Page():
      solara.SliderInt("空站門檻", value=門檻, min=0, max=5)
      表 = 各區空站比例(當時, 門檻)

  這樣有兩個問題：

  1. 值改不到。value=門檻 只是把數字 0
     交給滑桿，滑桿沒辦法回頭改你的變數。就算拉動滑桿，門檻 還是 0。
  2. **就算改到了，也沒人通知。**一般變數被改掉時不會發出任何訊號，Solara
     不知道要重新執行 Page()，圖表就停在舊的樣子。

  還有一個部署時才會發現的差別

  部署到 HuggingFace 之後，可能有好幾個人同時開你的 App。

  - 一般的全域變數是所有人共用一份。A 同學拉了滑桿，B 同學的畫面也可能跟著被改。
  - 寫在元件外面的 solara.reactive，Solara
    會幫每個使用者各存一份，彼此不互相干擾。

  那 df、時段們 為什麼是一般變數？

  因為它們讀進來之後就不會再變，不需要通知任何人。判斷原則是：

  ┌────────────────────────┬─────────────────┬──────────────────────────────┐
  │ 會被使用者操作改變嗎？ │     用什麼      │             例子             │
  ├────────────────────────┼─────────────────┼──────────────────────────────┤
  │ 會                     │ solara.reactive │ 門檻、時段、之後的行政區選單 │
  ├────────────────────────┼─────────────────┼──────────────────────────────┤
  │ 不會                   │ 一般變數        │ df、時段們、DATA_PATH        │
  └────────────────────────┴─────────────────┴──────────────────────────────┘

  所以上一題的行政區選單，選項清單 行政區們 用一般變數，目前選了哪一區的 行政區
  則要用 solara.reactive。

     計畫：把「臺大公館校區」的 65 站依經緯度歸回真正的行政區

     背景

     data/03_youbike_snapshots_clean.csv 的 sarea 欄有 13
     種值，其中「臺大公館校區」（sno 開頭 500119，65 站）不是行政區，而是
     YouBike 自己另外分出來的區。App 把 sarea 當成行政區做比較，所以圖上會多一個
     不是行政區的長條，而且大安區、中正區會少算這些站。

     做法：用臺北市行政區界線，對這 65
     站做空間連結（point-in-polygon），把它們的 sarea
